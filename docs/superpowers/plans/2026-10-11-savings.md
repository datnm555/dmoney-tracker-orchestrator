# Savings (Tiết kiệm) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tiết kiệm page showing total savings and the balance per account ("Nơi gửi"), computed from `savings`-category transactions, plus an optional `SavingsBank` field on transactions.

**Architecture:** Optional free-text `Transaction.SavingsBank` (mirrors `Bank`: normalize + max-length guard) threaded through create/update/response; new read-only `GET /savings/summary` (no planId) groups savings-category rows by `SavingsBank` (null bucket = unassigned). FE: conditional "Nơi gửi" chip block in the transaction form (only when the picked category's code is `savings`) and a new `/app/savings` page.

**Tech Stack:** unchanged (.NET 10 CQRS/EF, React 19/vitest).

**Spec:** `docs/superpowers/specs/2026-10-11-savings-design.md` (orchestrator repo) — the response records, resx block and error code there are verbatim requirements.

## Global Constraints

- Repos: BE `../dmoney-tracker-be` (HEAD e49d8da), FE `../dmoney-tracker-web` (HEAD ff644e2); continue on `feature/gold` (open PRs be#11 / web#8 absorb commits). Never commit code in the orchestrator repo.
- `SavingsBank` mirrors `Bank` exactly: `Normalize()` (trim, empty → null), `TransactionConstants.SavingsBankMaxLength = 100`, `TransactionErrors.SavingsBankTooLong = Error.Validation("Transactions.SavingsBankTooLong", ...)`. No guard on category, no FK.
- Every appended record param is trailing-optional (`string? SavingsBank = null`); `Transaction.Create/Update` gain trailing `string? savingsBank = null`.
- The explicit `UpdateTransactionRequest` (Web.Api/Endpoints/Transactions/UpdateTransaction.cs) MUST hand-thread `SavingsBank` with an update-path integration test (historical failure mode — memory).
- Savings rows = `t.UserId == userId` AND `t.CategoryId` in `dbContext.Categories.Where(c => c.Code == "savings").Select(c => c.Id)`. No plan filter. Debit = deposit, credit = withdrawal.
- Migration: `dotnet dotnet-ef migrations add AddTransactionSavingsBank --project src/Infrastructure --startup-project src/Web.Api --output-dir Database/Migrations` (scaffold untouched).
- Handlers `internal sealed`, explicit DI registration. resx keys verbatim from the spec, identical order in both files.
- FE: savings category detection uses the category's real `code` (`useCategoryDisplay().options[].code` is the category **id**, not the code — look up the categories context/list by id and compare its `code` to `'savings'`).
- BE gates: `dotnet build DMoney.slnx` (zero warnings) && `dotnet test DMoney.slnx`. FE gates: `npm test && npm run build && npm run lint` (no NEW warnings). Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Category switched away from Tích luỹ after picking a Nơi gửi → payload must carry `savingsBank: null` (test in Task 3).
- Editing an old savings row without Nơi gửi → form opens with nothing selected and saving keeps null (Task 3 edit test).
- Withdrawals larger than deposits on one account → negative balance rendered with "−", not "+-" (Task 4 page test).
- Whitespace-only Nơi gửi → stored null, lands in unassigned bucket (Task 1 test).
- Another user's savings and non-savings categories never leak into the summary (Task 2 test).

### Task 2: BE — `GET /savings/summary` + resx, push

**Files:** Create `src/Application/Savings/{GetSavingsSummaryQuery.cs,GetSavingsSummaryQueryHandler.cs,Data/SavingsSummaryResponse.cs}`, `src/Web.Api/Endpoints/Savings/GetSavingsSummary.cs` (mirror `Endpoints/Gold/GetGoldSummary.cs`), `tests/Api.IntegrationTests/Savings/SavingsSummaryEndpointTests.cs` (mirror `Gold/GoldSummaryEndpointTests.cs`); Modify `src/Application/DependencyInjection.cs`, `src/Web.Api/Resources/SharedResource.{vi,en}.resx`.

**Interfaces (verbatim from spec):**

```csharp
public sealed record SavingsSummaryResponse(
    MoneyResponse TotalBalance,
    IReadOnlyList<SavingsAccountResponse> Accounts,
    IReadOnlyList<SavingsTransactionResponse> Transactions);

public sealed record SavingsAccountResponse(
    string? SavingsBank, MoneyResponse Balance, MoneyResponse TotalDeposited,
    MoneyResponse TotalWithdrawn, int TransactionCount);

public sealed record SavingsTransactionResponse(
    Guid TransactionId, DateOnly Date, string Content, string? SavingsBank, string? Bank,
    MoneyResponse Credit, MoneyResponse Debit, Guid PlanId, string? SubCategoryName, string? Note);
```

Accounts ordered: assigned accounts by balance desc (ties by name), the null bucket last. Transactions: date desc, then CreatedAt desc. Currency `Money.DefaultCurrency`.
